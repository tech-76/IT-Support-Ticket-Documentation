# Incident Response Documentation Lab

## Overview

This lab demonstrates basic incident response documentation for common IT and cybersecurity scenarios. It focuses on how incidents are reported, investigated, escalated, contained, resolved, and reviewed.

This project is designed for IT Support, Service Desk, Desktop Support, Technical Support, and entry-level cybersecurity portfolio use.

## Lab Objectives

- Practice documenting security-related incidents
- Follow a structured incident response workflow
- Identify user impact and business risk
- Record investigation steps clearly
- Document containment and resolution actions
- Create post-incident review notes
- Demonstrate escalation awareness

## Incident Response Workflow

1. Identification
2. Documentation
3. Triage
4. Investigation
5. Containment
6. Escalation if required
7. Resolution
8. Recovery
9. Post-incident review

## Example Scenario: Phishing Email Report

### Incident Summary

A user reported receiving a suspicious email that appeared to request urgent password verification. The email included a link directing the user to a login page.

### User Impact

The user was concerned that the email may have been malicious. No credentials were entered and no files were downloaded.

### Initial Questions

- Did you click the link?
- Did you enter your username or password?
- Did you download any attachments?
- Did you forward the email to anyone else?
- Are you seeing any unusual account activity?
- What time was the email received?

### Investigation Notes

1. Confirmed the user did not click the link.
2. Confirmed no credentials were entered.
3. Reviewed the sender address for suspicious formatting.
4. Checked the email subject and message content.
5. Identified urgency-based language and suspicious link behavior.
6. Advised the user not to interact with the message.
7. Reported or flagged the message according to the security process.
8. Documented the incident and user response.

### Containment Actions

- User instructed not to click links or download attachments
- Suspicious message reported
- Email retained for review if required
- User advised to delete the message after reporting
- No password reset required because credentials were not entered

### Resolution

The message was treated as a phishing attempt. The user did not interact with the link or provide credentials. No further account compromise indicators were reported.

### User Communication

The user was thanked for reporting the suspicious email. The user was reminded to report suspicious emails immediately and avoid clicking unknown links.

## Example Scenario: Suspicious Login Activity

### Incident Summary

A user reported receiving an unfamiliar multi-factor authentication prompt.

### Investigation Notes

1. Confirmed whether the user attempted to sign in.
2. Asked the user not to approve unexpected MFA prompts.
3. Reviewed the time and location of the prompt.
4. Recommended a password reset if suspicious activity was suspected.
5. Escalated for further review if unauthorized login attempts continued.

### Containment Actions

- User denied unexpected MFA prompt
- Password reset recommended
- Account activity review requested
- Escalation recommended for repeated attempts

## Post-Incident Review Template

### What Happened?

Describe the incident clearly and briefly.

### What Was Affected?

List affected users, systems, accounts, or services.

### What Actions Were Taken?

Document investigation, containment, escalation, and resolution steps.

### Was Escalation Required?

Explain whether the incident was resolved at the support level or escalated.

### What Can Be Improved?

List recommendations such as user training, stronger MFA awareness, improved filtering, or better reporting procedures.

## Escalation Triggers

Escalate if:

- User entered credentials into a suspicious site
- Malware attachment was opened
- Unauthorized login was confirmed
- Multiple users received the same phishing email
- Sensitive data may have been exposed
- Endpoint compromise is suspected
